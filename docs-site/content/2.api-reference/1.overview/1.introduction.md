## Base URL

```text
https://logstrace.dev/api
```

## Authentication

Send a project [API key](/guides/teams/api-keys) as a bearer token:

```http
Authorization: Bearer lgk_...
```

| Status | Message |
|---|---|
| `401` | Missing or malformed key, or the key is revoked |
| `403` | The key doesn't have the access the endpoint needs (for example a read-only key on ingest) |

## Requests

- JSON bodies with `Content-Type: application/json`.
- A `Content-Length` header is required; chunked bodies are rejected with `411`.
- Ingest bodies are limited to 2 MB (`413` above that).

## Errors

Every error has the same shape:

```json
{ "statusCode": 400, "statusMessage": "Invalid event. events.3.level: Invalid option" }
```

| Status | Meaning |
|---|---|
| `400` | The body failed validation. The message names the field |
| `401` / `403` | See authentication above |
| `411` | `Content-Length` missing |
| `413` | Body too large |
| `429` | Rate limit reached. Wait for the `Retry-After` header (seconds) |
| `5xx` | Server problem. Retry with backoff |

## Rate limits

| Endpoint | Limit |
|---|---|
| `POST /api/ingest` | 1,200 requests per minute per key |
| `GET /api/v1/logs`, `GET /api/v1/logs/trace/:id` | 120 requests per minute per key |

Limits are shared across all servers, so spreading requests over machines doesn't raise them. Batch events instead: one request can carry 500.
