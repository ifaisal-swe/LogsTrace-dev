LogsTrace has an [MCP](https://modelcontextprotocol.io) endpoint. An AI assistant connected to it can list your tables and query your logs, but can't change anything.

## Connect

1. **API keys** → create a key with **Read logs** access. Leave *Show IPs, emails and tokens* off unless the assistant needs them.
2. Open **Connect an AI assistant (MCP)** under the new key and copy the settings into your MCP client:

```json [mcp.json]
{
  "mcpServers": {
    "logstrace": {
      "url": "https://logstrace.dev/api/mcp",
      "headers": { "Authorization": "Bearer lgk_..." }
    }
  }
}
```

## Tools

| Tool | Does |
|---|---|
| `list_tables` | Tables, their columns (by number) and message counts |
| `search_messages` | Latest messages by text, level, channel or table |
| `find_value` | Every message containing one value, across tables |
| `query_table` | Rows or a summary (group, count, sum, average…) of one table |
| `run_plan` | Up to 6 steps in order; a step can filter by values from an earlier one |

All tools are read-only and work on the key's project only.

::warning
Whatever the tools return goes to your assistant's AI provider. Use a masked key unless you need the hidden values, and revoke the key when you stop using it.
::

## Limits

- 60 requests per minute per key; one query at a time per key.
- Each call returns at most 100 rows per step and stops after 15 seconds.
- Log text is data from your applications: a message can't make the assistant do anything LogsTrace allows only for people.
