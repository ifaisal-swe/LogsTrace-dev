Keys belong to one project and start with `lgk_`. Admins and owners manage them under **API keys** in the project.

## Access

| Access | Use for |
|---|---|
| **Send logs** | Servers and apps. Can only write, so a leaked key can't read your data |
| **Read logs** | Scripts and tools that query logs through the [read API](/api-reference/endpoints/query-logs) |
| **Send and read** | Both |

Read keys can also get **Show IPs, emails and tokens**. Only someone who can see those values themselves can give a key that option.

## Storing keys

- The full key is shown **once**. LogsTrace stores only a SHA-256 hash.
- Put it in an environment variable or secret store, never in source code or client-side code (browsers, mobile apps).
- Use one key per service so you can revoke one without touching the others. The list shows when each key was last used.

## Rotating

1. Create a new key and deploy it.
2. Check that **Last used** on the old key stops moving.
3. Revoke the old key. It stops working within a minute.

Creating and revoking keys is recorded in the audit log.
