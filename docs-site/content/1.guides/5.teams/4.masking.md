Members and viewers see sensitive values masked. Admins and owners see everything.

| Found in text | Shown as |
|---|---|
| IPv4 address `203.0.113.7` | `•.•.•.•` |
| IPv6 address | `••••:••••` |
| Email `ana@example.com` | `••••@••••` |
| `Bearer <token>` | `Bearer ••••` |
| Keys like `sk_…`, `pk_…`, `rk_…`, `lgk_…`, `ghp_…`, `gho_…` | `••••` |

In `data`, these keys are fully masked whatever their value: `ip`, `ipv4`, `ipv6`, `email`, `phone`, `token`, `access_token`, `refresh_token`, `password`, `secret`, `authorization`, `api_key`.

## Where it applies

Everywhere: Logs, tables, search, column profiles, dashboards, CSV exports and the live stream.

Search and filters run **on the masked text** for people without access, so they can't find out which messages contain a given email or IP by searching for it.

## Columns stay in place

Masks never add or remove spaces, so a masked message still lines up with its table's columns.

::warning
Masking is a safety net, not a vault. Admins see the values, and formats it doesn't recognise (names, addresses, card numbers) are not masked. Don't send data you wouldn't want an admin to read.
::
