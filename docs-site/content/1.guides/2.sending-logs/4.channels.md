A channel is a free label, up to 100 characters. Pick one per area of your system:

```text
orders · payments · auth · email · worker · cron
```

- Tables are built **per channel**: the same sentence in `orders` and `payments` becomes two tables.
- Logs, search, dashboards and saved views can all filter by channel.
- An event without a channel goes to the empty channel (shown as `—`).

## Set it once per request

If a sender only writes to one channel, set the header instead of repeating the field:

```bash
curl -X POST https://logstrace.dev/api/ingest \
  -H "Authorization: Bearer $LOGSTRACE_KEY" \
  -H "X-LogsTrace-Channel: worker" \
  -H "Content-Type: application/json" \
  -d '[{"text":"Job 551 started"},{"text":"Job 551 finished in 1.82 s"}]'
```

A `channel` (or `service`, `resource`, `source`) on the event wins over the header.

::tip
Use projects for environments (`production`, `staging`) and channels for areas inside one environment.
::
