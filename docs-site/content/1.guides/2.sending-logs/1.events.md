An event is one log entry. Send it as JSON to `POST /api/ingest`, either as an **object with fields** (recommended) or as a **message**.

::code-group
```json [Structured (recommended)]
{
  "channel": "payments",
  "level": "warn",
  "event": "payment.declined",
  "paymentId": "8813",
  "orderId": "10294",
  "amount": 120.00,
  "currency": "USD",
  "ts": "2026-10-06T09:12:00Z",
  "traceId": "req-7f3a9c"
}
```

```json [Message]
{
  "channel": "payments",
  "level": "warn",
  "text": "Payment 8813 for order 10294 declined 120.00 USD",
  "ts": "2026-10-06T09:12:00Z",
  "traceId": "req-7f3a9c",
  "data": { "gateway": "stripe", "attempt": 2 }
}
```
::

## Structured events

Send an object without `text`: every key that isn't one of the fields below becomes a **column with that name**. All `payment.declined` events in a channel go to one table with the columns `paymentId`, `orderId`, `amount` and `currency`, from the very first event. No guessing, no renaming.

- `event` names the table (optional, up to 100 characters of letters, digits and `- _ . :`). Events with the same name and the same keys share a table, in any key order; a new key makes a new table.
- Nested objects become dotted columns: `{ "user": { "id": "42" } }` → `user.id`. Arrays are kept as JSON in one column.
- Up to 50 fields per event, values up to 512 characters in the table. The original object is also stored in `data`, so [data filters](/guides/exploring/logs) work on it.
- The log line lists keys alphabetically: `payment.declined amount: 120 currency: USD orderId: 10294 paymentId: 8813`. Spaces inside a value show as `_` there; `data` keeps the original.
- Don't use the names below (or their aliases, like `source`, `time`, `meta`) as your own field names: they are read as the event's channel, time, and so on.
- `data` stays extra JSON next to the columns (it becomes the columns only if there are no other top-level keys).
- Extra keys on a message (`{ "text": "…", "userId": "42" }`) are added to its `data`.

## Fields

::field-group
  :::field{name="text" type="string"}
  The message, up to 16 KB. Leave it out to send a structured event.
  :::

  :::field{name="event" type="string"}
  Name of a structured event, for example `order.paid`. Optional.
  :::

  :::field{name="channel" type="string"}
  Any label up to 100 characters, for example `orders`. Tables are built per channel. Defaults to the `X-LogsTrace-Channel` header, else empty.
  :::

  :::field{name="level" type="string | number"}
  `debug`, `info`, `warn`, `error` or `fatal`. Defaults to `info`. See [Levels](/guides/sending-logs/levels).
  :::

  :::field{name="ts" type="string | number"}
  When it happened: ISO 8601, Unix seconds or Unix milliseconds. Missing, invalid, or more than 7 days away from now → the time LogsTrace received it.
  :::

  :::field{name="data" type="object"}
  Your own JSON, up to 32 KB. Stored and shown with the log, masked for viewers.
  :::

  :::field{name="traceId" type="string"}
  Groups events from one request or job. Up to 128 characters of letters, digits and `- _ . :`. See [Tracing](/guides/sending-logs/tracing).
  :::

  :::field{name="spanId" type="string"}
  Identifies one step inside a trace. Same format as `traceId`.
  :::

  :::field{name="embed" type="object"}
  Rich message: `{ title, description, fields: [{ name, value }] }` (≤25 fields). Flattened into `text`, so it is grouped into tables like any message.
  :::
::

## Field names from other loggers

You don't have to rename fields to switch to LogsTrace. These names are accepted too:

| LogsTrace | Also accepted |
|---|---|
| `text` | `message`, `msg`, `body` |
| `ts` | `timestamp`, `time`, `@timestamp` |
| `channel` | `service`, `resource`, `source` |
| `level` | `severity`, `severityText` |
| `data` | `metadata`, `meta`, `attributes` |
| `traceId` | `trace_id`, or `traceId` / `trace_id` inside `data` |
| `spanId` | `span_id`, `parentId`, `parent_id`, or inside `data` |

So a typical pino, winston or OpenTelemetry-style record works as is:

```json
{ "time": 1759741920000, "level": 50, "msg": "Payment 8813 declined", "service": "payments" }
```
