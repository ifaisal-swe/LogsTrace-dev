The request body can be one event, an array of events, or `{ "events": [...] }`.

::code-group
```json [Object]
{ "events": [
  { "channel": "payments", "text": "Payment 8812 for order 10293 captured 49.90 USD" },
  { "channel": "payments", "level": "warn", "text": "Payment 8813 for order 10294 declined 120.00 USD" }
] }
```

```json [Array]
[
  { "channel": "payments", "text": "Payment 8812 for order 10293 captured 49.90 USD" },
  { "channel": "payments", "level": "warn", "text": "Payment 8813 for order 10294 declined 120.00 USD" }
]
```
::

Response: `{ "accepted": 2, "status": "ok" }`

## Limits

| Limit | Value |
|---|---|
| Events per request | 1–500 |
| Body size | 2 MB |
| Requests per key | 1,200 per minute |
| `text` | 16 KB |
| `data` | 32 KB per event |

A batch is all-or-nothing: if one event is invalid, the whole request is rejected with `400` and a message naming the event, for example `Invalid event. events.3.level: …`.

## Recommended pattern

Buffer events in memory and flush every second or every 200 events, whichever comes first. On `429`, wait for the time in the `Retry-After` header and retry the same batch. See the [integrations](/guides/integrations/http) for ready-made senders.
