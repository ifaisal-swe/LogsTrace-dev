## Organizations and projects

| Concept | What it is |
|---|---|
| **Organization** | Your team. Members and roles live here. |
| **Project** | One app, service or environment. Logs, API keys, tables and dashboards belong to a project. |

Each gets an address (slug) made from its name, for example `checkout-api`. Renaming keeps the address, so links and scripts keep working.

## Channels

A **channel** is any label you choose for a stream of messages: `orders`, `payments`, `auth`, `worker`. Tables are built per channel, so messages in different channels never mix.

Set it per event (`channel`) or for a whole request with the `X-LogsTrace-Channel` header.

## Tables and columns

LogsTrace compares each new message with the earlier messages of the same channel and length. When most words match, they belong to the same **table**; the words that differ become **columns**.

```text
Payment 8812 for order 10293 captured 49.90 USD
Payment 8813 for order 10294 declined 120.00 USD
```

becomes the table `Payment <*> for order <*> <*> <*> USD` with four columns:

| field_1 | field_2 | field_3 | field_4 |
|---|---|---|---|
| 8812 | 10293 | captured | 49.90 |
| 8813 | 10294 | declined | 120.00 |

- Columns start as `field_1`, `field_2`… in reading order. Rename them (`payment_id`, `order_id`, `status`, `amount`) and the names stick, even when the table later gains columns.
- Words containing digits are treated as values from the start, so IDs group immediately.
- Column values are read from the message at query time, so filters stay correct as tables evolve.

::note
Messages with a different word count land in a different table. Keep variable-length text (free-form notes, stack traces) at the end of a message or in `data`. See [Best practices](/guides/sending-logs/best-practices).
::

## Levels

Every message has a level: `debug`, `info` (default), `warn`, `error` or `fatal`. Names from other loggers are mapped automatically, see [Levels](/guides/sending-logs/levels).

## Data

`data` is your own JSON object (up to 32 KB) stored next to the message. It's shown with the log and masked for viewers, but it isn't used to build tables.
