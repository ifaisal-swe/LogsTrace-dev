Open **Alerts** in a project. Admins and owners can create them.

## Conditions

| Alert me when | Options | Checked |
|---|---|---|
| A message at or above a level | Warning or worse, Error or worse, Fatal only; optional channel and table | On every ingest |
| A new kind of message (new table) | — | On every ingest |
| Too many messages in a time window | At least N messages within M minutes; optional level, channel and table | Every minute |

After an alert fires it stays quiet for its **quiet period** (1–1,440 minutes), so a burst of errors sends one message, not hundreds.

## Destinations

| Destination | URL |
|---|---|
| Discord | Channel settings → Integrations → Webhooks → Copy URL |
| Slack | An Incoming Webhook URL (`hooks.slack.com/services/…`) |
| Webhook (JSON) | Any public `https` endpoint. Receives a JSON `POST` |

Use **Send test** to check the destination before relying on it.

### JSON webhook body

```json
{
  "rule": { "id": "…", "name": "Checkout errors" },
  "title": "…",
  "details": ["…"],
  "link": "https://logstrace.dev/o/acme/p/checkout-api/logs?…",
  "event": { "level": "error", "channel": "checkout", "text": "Payment 8813 failed for user ••••@••••", "ts": "2026-10-06T09:12:00.000Z", "templateId": "…" }
}
```

`event` is `null` for volume alerts.

## Safety

- Message text in alerts is **always masked**, whoever created the alert: it leaves LogsTrace.
- Webhook URLs must use `https` on the default port and resolve to a public address. Private and local addresses are refused.
- Saved URLs are shown shortened in the list, since they work like passwords.
