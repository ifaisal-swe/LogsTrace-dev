The AI doesn't read or search your logs. It writes a short **plan**: a few steps in a fixed, read-only query language. You see the plan in plain words, then LogsTrace runs it with **your own access**.

## Ask a question

**Search → Ask**, then type a question:

```text
Which users had failed payments, and what were their slowest requests?
```

You get a plan like:

1. **Users with failed payments**: count of *payment failed* by *user*.
2. **Their slowest requests**: rows of *request* where *user* is one of the users from step 1, by *duration* high to low.

Change the time range, or type a change (`only the last hour`, `top 20`, `split by channel`) and select **Update plan**. Select **Run plan** to see the results. The last step is the answer.

## Build a dashboard

**Dashboards → Build with AI**: describe what you need to see. You get a name and a list of panels to check before anything is saved. While editing a dashboard, **Add with AI** adds panels to it.

## Name tables

**Tables → Name with AI** names tables and `field_N` columns that nobody has named yet. Names you chose are never changed.

## What the AI sees

| Sent to the AI provider | Never sent |
|---|---|
| Your question (emails, IPs and tokens removed) | Query results |
| Table patterns and column names | Full messages |
| Up to 3 recent values per column, masked | Unmasked IPs, emails, tokens |

::note
Plans run read-only, with your role's masking, within 15 seconds. Viewers can ask questions; building dashboards and naming tables need the **member** role.
::

AI is optional and set up by whoever runs LogsTrace. Without it, these buttons don't appear.
